# 관리자 관리 UI 개선 기획

- 기능 ID: staff-ui
- 상태: 확정
- 최종 갱신: 2026-10-22
- 작업계획: [계획](../plans/staff-ui.md)
- 현재 기능 문서: [직원 인증·관리](../features/admin-auth.md)
- 관련 기준: [UI 가이드](../architecture/ui-guide.md), [입력·버튼 크기 수정안](../plans/admin-auth.md)

## 목적 및 범위

관리자 관리 페이지를 목록 중심으로 정리한다. 상시 노출된 서브관리자 생성 폼은 버튼으로 여는 모달로 바꾸고, 행별 관리 버튼은 더보기 팝오버 메뉴 하나로 묶는다. 앞선 입력·버튼 크기 통일 요청도 포함한다.

## 화면 및 사용자 흐름

- 목록 패널 상단: 왼쪽 직원 목록 제목, 오른쪽 목록 새로고침·서브관리자 생성 버튼. 모바일에서는 줄바꿈한다.
- 생성 버튼을 누르면 이름·이메일·초기 비밀번호를 세로 배치한 모달을 연다. 비밀번호 규칙과 별도 전달·최초 변경 안내를 유지한다. 하단에 취소·계정 생성 버튼을 둔다.
- 생성 성공 시 모달을 닫고 목록을 갱신하며 성공 메시지를 표시한다. 실패 시 입력값을 유지하고 모달 안에 오류를 표시한다. 취소 후 다시 열면 빈 폼으로 시작한다.
- 서브관리자 행에는 접근성 이름에 대상을 포함한 더보기 버튼 하나를 표시한다. 클릭하면 버튼에 연결된 팝오버 메뉴에서 이름 수정·비활성화/재활성화·비밀번호 재설정을 선택한다.
- 메뉴 선택 시 메뉴를 닫고 기존 기능의 편집·확인 모달을 연다. 관리자 행의 관리 칸은 기존처럼 대시로 표시한다.
- Escape·바깥 클릭으로 메뉴를 닫고 키보드로 열기·항목 이동·선택할 수 있다. 테이블 스크롤 영역에 메뉴가 잘리지 않도록 표시한다.

## 입력·버튼 기준 제안

로그인·비밀번호 변경·직원 생성 및 편집 모달의 입력과 폼 실행·취소 버튼 높이를 40px로 통일한다. 가로 배치 시 조작부 위아래 경계를 맞춘다. 기존 색·반경·작은 좌우 패딩을 유지한다. 표·헤더의 독립 조작 및 아이콘 버튼 크기는 기존 기준을 따른다. 확정 후 UI 가이드에 향후 필수 확인 항목으로 반영한다.

## 데이터·권한·예외

현재 인증·권한·API·비밀번호 정책을 유지한다. 처리 중 중복 제출과 모달 닫기를 막는다. 로딩·빈 목록·조회 실패·재시도 안내를 유지한다. 생성·편집 오류는 해당 모달 안에 표시하고 목록 오류와 구분한다.

서브관리자 삭제는 별도 [삭제 기획](staff-delete.md)·계획의 확인 대기 작업이다. 이번 기획은 현재 구현된 세 관리 기능의 노출 방식을 변경하며 삭제 구현을 포함하지 않는다. 삭제 구현 시 메뉴에 항목을 추가하도록 해당 작업 문서를 연계한다.

## 완료 기준

- [ ] 최초 진입 시 생성 폼 대신 생성 버튼과 직원 목록이 표시된다.
- [ ] 생성 모달에서 유효한 값 제출 시 생성·닫기·목록 갱신·성공 안내가 수행된다.
- [ ] 필수값 누락·비밀번호 규칙 위반·API 실패 시 성공 처리하지 않으며 수정·재시도할 수 있다.
- [ ] 취소 시 데이터가 변경되지 않고 다시 열면 빈 생성 폼이 표시된다. 처리 중에는 중복 요청·닫기가 차단된다.
- [ ] 각 서브관리자 행에는 더보기 버튼 하나가 있으며 올바른 대상·현재 상태에 맞는 메뉴와 편집 모달이 열린다.
- [ ] 메뉴의 바깥 클릭·Escape 닫기, 키보드 이동·선택 및 닫힌 뒤 포커스 복귀가 정상이다.
- [ ] 로그인·비밀번호·직원 폼의 입력과 폼 버튼이 40px로 일치한다. 비밀번호 보기 전환이 정상이다.
- [ ] 1440·768·390px에서 모달·메뉴가 화면 밖으로 잘리지 않고 테이블만 필요한 가로 스크롤을 제공한다.
- [ ] 관련 자동 테스트·린트·타입·빌드, 실제 브라우저 콘솔·네트워크 확인, 리뷰와 문서 갱신 후 사용자 최종 확인을 받는다.

## 미결 질문

- 없음. 사용자가 기획 확정 및 작업 진행을 지시함.

## 합의 및 변경 이력

- 2026-10-22: 사용자가 생성 버튼→모달, 행별 더보기→팝오버 메뉴 전환을 요청했다. 상세 기획 초안 작성. 코드 구현 전.

- 2026-10-22: 사용자 “확정하고 작업 진행하자” 지시로 기획 및 제시된 구현·검증 범위 승인.
