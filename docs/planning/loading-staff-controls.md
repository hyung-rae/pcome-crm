- 현재 기능 문서: [직원 인증·관리](../features/admin-auth.md), [대시보드](../features/dashboard-ui.md)
- 관련 기준: [UI 가이드](../architecture/ui-guide.md)

## 목적 및 범위

페이지 이동·데이터 조회 대기 상태를 시각적으로 표시하고 직원 목록을 아이콘·배지·상태 토글 중심으로 정리한다. 서버 권한과 기존 비활성 계정 접근 차단 정책은 유지한다.

## 화면 및 동작 제안

1. 페이지 이동: 라우트 응답 대기 중 접근성 안내를 포함한 브랜드색 스피너 또는 본문 스켈레톤을 표시한다. 대시보드·관리자 관리·비밀번호 변경·로그인 등 현재 앱 경로의 전환을 대상으로 한다. 빠른 전환을 위해 인위적인 지연은 넣지 않는다. 인증 확인 중 기존 계정 정보나 업무 데이터를 먼저 노출하지 않는다.
2. 직원 목록 최초 조회: 표 모양 스켈레톤과 읽는 중 안내를 표시한다. 새로고침 시 기존 행은 유지하고 새로고침 아이콘의 로딩 표시 및 aria-busy로 갱신 중임을 알린다. 조회 실패는 오류·재시도를 제공하고 빈 목록과 구분한다.
3. 목록 새로고침: 텍스트 대신 16px 새로고침 아이콘·32px 조작 영역·툴팁·접근성 이름을 제공한다. 요청 중 재실행을 막는다.
4. 권한: 목록과 공통 상단바의 관리자·서브관리자 표시는 작은 배지로 변경한다. 관리자 오렌지 연한 배경, 서브관리자 중립 회색 배경을 사용하며 텍스트도 유지해 색만으로 구분하지 않는다. 모바일 상단바는 기존 숨김 기준을 유지한다.
5. 상태: 서브관리자 행 상태 컬럼에 활성/비활성 텍스트를 동반한 토글을 제공한다. 관리자 행은 상태 표시만 제공하며 변경할 수 없다. 더보기 메뉴의 중복 활성화·비활성화 항목은 제거한다.
6. 토글은 별도 확인 모달 없이 해당 행 상태 변경을 즉시 요청하는 방식을 제안한다. 응답 성공 후 서버 결과를 반영하고 처리 중 상태는 유지한다. 실패 시 원래 상태를 유지하며 대상별 오류와 재시도 수단을 제공한다. 처리 중 중복 변경·삭제·재설정 등 충돌하는 조작을 막는다.

## 데이터·권한 및 예외

기존 PATCH 상태 변경 API와 관리자 권한 검증을 사용한다. 로그인 계정·본인·관리자 변경 제한은 그대로다. 현재 비활성화는 다음 요청부터 업무 접근을 차단하며 이를 토글 설명/툴팁으로 안내한다. 비활성화는 계정 삭제가 아니다. 성공 후 목록 재조회 실패는 변경 성공과 구분해 알린다. 동작 줄이기 설정에서 스켈레톤 애니메이션을 줄인다.

## 완료 기준

- [ ] 느린 페이지 이동에서 대기 표시가 보이고 목적지 로딩 완료·오류 시 해제된다. 인위적 지연이 없다.
- [ ] 목록 최초 조회에는 스켈레톤, 재조회에는 기존 행·새로고침 로딩 표시가 보인다. 실패를 빈 상태로 오인하지 않는다.
- [ ] 새로고침 버튼은 아이콘만 표시하며 키보드 조작·툴팁·접근성 이름을 제공하고 중복 요청을 막는다.
- [ ] 관리자·서브관리자 권한이 목록·상단바에서 배지로 구분된다.
- [ ] 서브관리자 상태 토글은 성공 시 해당 행만 올바른 상태로 갱신하고 실패 시 원래 상태·오류·재시도를 제공한다. 관리자 상태는 조작할 수 없다.
- [ ] 더보기 메뉴에 중복 상태 항목이 없고 이름 수정·재설정·삭제는 정상이다.
- [ ] 직접 권한 우회 거부·비활성 기존 세션 차단·중복 제출 방지 회귀를 확인한다.
- [ ] 1440·768·390px 및 키보드·상태 안내·콘솔·실패 요청을 확인하고 자동 테스트·린트·타입·빌드·리뷰·문서 갱신을 마친다.
