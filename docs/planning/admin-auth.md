# 로그인 및 관리자 관리 기획

- 기능 ID: admin-auth
- 상태: 확정
- 최종 갱신: 2026-10-22
- 작업계획: [작업계획](../plans/admin-auth.md) — 사용자 확정
- 현재 기능 문서: [로그인 및 관리자 관리](../features/admin-auth.md)

## 목적 및 사용자

헬스장 직원만 CRM에 접근하도록 Supabase Auth와 DB를 연결한다. 관리자와 서브관리자의 접근 권한을 구분한다. Supabase 무료 플랜, 이메일·비밀번호 로그인, 관리자의 이메일·초기 비밀번호 지정 생성, 관리자 권한과 최초·임시 비밀번호 변경 정책을 사용자 확인으로 확정했다. 기존 프로젝트 대신 사용자가 생성한 pcome-crm 프로젝트를 사용한다.

## 범위

- 이메일·비밀번호 로그인, 로그아웃, 로그인 유지, 비밀번호 변경
- 비로그인 사용자의 업무 화면 접근 차단
- 관리자 계정 목록, 서브관리자 생성·이름 수정·비활성화·재활성화
- Supabase Auth, 직원 프로필·권한·활성 상태 저장, DB 접근 정책
- 첫 관리자 계정은 초기 설정 절차에서 생성
- 공개 회원가입, 회원 관리, 다지점, 세부 권한 설정, 관리자 계정 영구 삭제는 제외. 서브관리자 삭제는 후속 staff-delete 기획에 따라 추가
- 서브관리자는 관리자가 이메일·초기 비밀번호를 지정해 직접 생성한다. 이메일 초대는 제외한다.
- 초기 비밀번호는 관리자가 별도 전달하며 최초 로그인 시 변경 필수. 분실 시 관리자가 임시 비밀번호를 재설정하고 다시 변경을 강제한다.

## 사용자 흐름

1. 비로그인 상태로 접속하면 로그인 화면으로 이동한다.
2. 이메일·비밀번호를 입력한다. 인증과 직원 활성 상태 확인에 성공하면 대시보드로 이동한다.
3. 관리자는 관리자 관리 화면에서 직원 목록을 확인하고 서브관리자를 관리한다.
4. 서브관리자는 대시보드를 이용하고 본인 비밀번호를 변경한다.
5. 로그아웃하면 로그인 화면으로 돌아간다.

## 화면 및 동작

- 로그인: 이메일·비밀번호, 입력 검증, 제출 중 중복 요청 방지, 인증 실패·연결 실패 표시
- 공통 화면: 로그인한 직원 이름·역할, 로그아웃, 본인 비밀번호 변경
- 관리자 관리: 이름·이메일·역할·상태 목록과 서브관리자 생성·수정·상태 변경
- 기존 UI 가이드와 대시보드 레이아웃 재사용
- 권한 없는 직접 URL·API 접근도 거부하며 메뉴 숨김에만 의존하지 않는다.

## 데이터 및 권한

- 비밀번호와 인증은 Supabase Auth가 관리하며 앱 테이블에 비밀번호를 저장하지 않는다.
- 직원 프로필: Auth 사용자 ID, 이름, 역할(admin/sub_admin), 활성 상태, 생성·수정 시각
- 관리자: 직원 목록 조회와 서브관리자 생성·이름 수정·활성 상태 변경
- 서브관리자: 본인 프로필 조회와 비밀번호 변경, 대시보드 접근
- 이번 UI에서 관리자 추가·승격·강등은 제공하지 않는다.
- 서버와 DB에서 권한·활성 상태를 검증한다. 사용자 편집 가능 메타데이터를 권한 근거로 쓰지 않는다.
- 노출 테이블에는 RLS와 최소 권한을 적용한다. 서버 전용 비밀 키를 브라우저에 전달하지 않는다.
- 업무 데이터의 직원별 권한은 해당 기능 기획 시 별도 확정한다.

## 예외 및 정책

- 공개 가입을 허용하지 않고, 인증에 성공하더라도 직원 프로필이 없거나 비활성 상태면 업무 접근을 거부한다.
- 서브관리자 비활성화 후 다음 서버 요청·DB 접근부터 차단한다. 이미 화면에 표시된 정보의 원격 삭제는 보장하지 않는다.
- 중복 이메일 생성은 실패 처리하고, Auth와 프로필의 일부만 생성되는 경우 복구 방법을 작업계획에 정의한다.
- 관리자 본인 비활성화와 마지막 관리자 제거는 제공하지 않는다.
- DB 프로젝트 선택·현황 조사 후 기존 데이터에 영향을 주지 않는 연결·스키마 계획을 작성한다.

## 완료 기준

- [x] 활성 관리자·서브관리자가 올바른 이메일·비밀번호로 로그인하면 대시보드에 접근한다.
- [x] 잘못된 자격 증명은 로그인에 실패하고 보호된 데이터가 반환되지 않는다.
- [x] 비로그인 상태로 보호 화면·서버 작업을 요청하면 접근이 차단된다.
- [x] 새로고침 후 유효한 로그인이 유지되고 로그아웃 후 보호 화면에 접근할 수 없다.
- [x] 관리자가 서브관리자를 생성하면 Auth 계정과 직원 프로필이 일치하고 해당 계정으로 로그인할 수 있다.
- [x] 중복 이메일·필수값 누락은 실패하며 일관되지 않은 직원 계정이 남지 않는다.
- [x] 서브관리자는 URL·서버 요청·DB 직접 요청으로 다른 직원 조회·수정 및 본인 권한 변경을 할 수 없다.
- [x] 비활성화된 서브관리자는 기존 세션을 포함해 다음 보호 요청에서 차단된다.
- [x] 재활성화한 계정은 다시 로그인할 수 있다.
- [x] 본인 비밀번호 변경 후 새 비밀번호로 로그인할 수 있고 이전 비밀번호는 실패한다.
- [x] Supabase 연결 실패 시 명확한 오류를 표시하며 인증·권한 검증을 우회하지 않는다.
- [x] 자동 테스트, 린트·타입 검사·빌드, PC·모바일 실제 브라우저 검증, 코드 리뷰 결과를 기록한다.

## 확정 정책 및 운영 준비

- 관리자는 서브관리자 생성·이름 수정·비활성화·재활성화 가능. 서브관리자는 직원 관리 불가.
- 확정: 관리자가 별도 전달, 최초 로그인 변경 필수, 분실 시 관리자 임시 비밀번호 재설정 및 다시 변경 필수. 첫 관리자 복구는 Supabase 소유자의 운영 절차로 별도 기록한다.
- 사용자가 생성한 `pcome-crm` 프로젝트(`ligmwstlapvwaxovhgny`, ap-south-1)를 사용한다. [연결 설정과 검증 범위](../architecture/supabase.md)를 참고한다.

## 합의 및 변경 이력

- 2026-10-22: 사용자 요청에 따라 로그인·관리자·서브관리자·Supabase DB 연결 기획 초안 작성. 무료 플랜 사용 지정. 세부 정책과 기획은 확정 전이며 기능 코드·원격 DB 변경 없음.
- 2026-10-22: 사용자가 이메일·비밀번호 로그인, 관리자 이메일·초기 비밀번호 지정 생성, 기존 프로젝트와 다른 Supabase 프로젝트 사용을 확정. 전체 기획·작업계획은 확정 전이다.
- 2026-10-22: 사용자가 생성한 pcome-crm 프로젝트 연결 요청. 로컬 환경변수를 설정하고 관리 커넥터 DB 읽기 검증 완료. 앱 연동·인증·스키마 변경은 아직 수행하지 않음.

- 2026-10-22: 사용자가 기획·작업계획 및 관리자 권한·최초 비밀번호 변경·관리자 임시 비밀번호 재설정을 확인하여 확정.

- 2026-10-22: 구현·자동 검증·브라우저 검증·개발 후 리뷰·문서 반영 후 최종 사용자 확인 대기.

- 2026-10-22: 사용자가 비밀번호 길이만 8~16자로 변경하도록 요청. 영문·숫자 포함 조건 유지. 비밀번호 변경 UI에도 로그인 UI 보정 사항을 적용하도록 요청하여 기존 기능 문서와 계획에 반영.

- 2026-10-22: [서브관리자 삭제 후속 기획](staff-delete.md)과 작업계획을 사용자와 확정했다. 최초 범위에서 제외했던 영구 삭제를 서브관리자에 한해 추가하며 관리자 삭제·복구는 계속 제외한다.
