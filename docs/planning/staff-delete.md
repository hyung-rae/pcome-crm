# 서브관리자 삭제 기획

- 기능 ID: staff-delete
- 상태: 확정
- 최종 갱신: 2026-10-22
- 작업계획: [계획](../plans/staff-delete.md) — 사용자 확정
- 현재 기능 문서: [직원 인증·관리](../features/admin-auth.md)

## 목적과 범위

사용자가 관리자만 서브관리자를 확인창을 거쳐 삭제하고 로그인 계정과 직원 정보를 함께 삭제하는 방식을 승인했다. 활성·비활성 서브관리자 모두 대상이다. 관리자 계정·본인 삭제, 복구·일괄 삭제·회원 데이터 삭제는 제외한다.

## 사용자 흐름과 화면

관리자 관리 목록의 서브관리자 행 더보기 메뉴에 삭제 항목을 추가한다([UI 개선](staff-ui.md) 연계). 기존 Modal 패턴에 대상 이름·이메일, 로그인 계정과 직원 정보가 영구 삭제되어 복구할 수 없다는 안내, 삭제·취소 버튼을 표시한다. 취소·닫기는 아무 데이터도 변경하지 않는다. 처리 중에는 중복 제출과 닫기를 막는다. 성공하면 창을 닫고 목록을 갱신하며 실패하면 창 안에서 오류와 재시도 방법을 안내한다.

## 데이터·권한과 예외

- 서버에서 현재 활성 관리자 권한·최초 비밀번호 변경 완료 여부를 검증한다.
- 대상 staff.role=sub_admin을 확인하고 관리자·본인·없는 대상 삭제를 거부한다. 클라이언트의 역할 값을 신뢰하지 않는다.
- 서버 관리 키로만 삭제한다. Auth 계정 삭제와 현재 FK의 ON DELETE CASCADE로 연결된 staff 삭제를 처리한다.
- 기존 세션 차단과 부분 실패 처리는 작업계획에 명시한다. 삭제 후 기존 토큰으로 업무 API·DB 접근도 거부해야 한다.
- 이미 삭제된 대상·잘못된 ID·권한 없음·연결 실패를 성공으로 표시하지 않는다.
- 현재 회원 테이블은 없다. 향후 회원·상담 기록을 연결할 때 등록 직원 삭제로 업무 기록이 함께 삭제되지 않도록 별도 FK 정책을 확정한다.

## 완료 기준

- [x] 관리자만 서브관리자 행의 삭제 동작을 사용할 수 있고 관리자 행에는 삭제 버튼이 없다.
- [x] 확인창에 정확한 대상·영구 삭제 안내가 표시되고 취소 시 계정이 유지된다.
- [x] 확인하면 해당 Auth 계정과 staff만 삭제되고 다른 계정은 유지된다.
- [x] 삭제된 계정은 재로그인·기존 세션 업무 요청·직접 DB 요청이 거부된다.
- [x] 비로그인·서브관리자·초기 비밀번호 계정의 직접 삭제 요청이 거부된다.
- [x] 관리자·본인·잘못된 ID·없는 대상을 직접 요청해도 삭제하지 않는다.
- [x] 삭제 실패·중복 제출을 처리하며 성공 여부와 실제 데이터가 일치한다.
- [x] PC·태블릿·모바일 확인창과 키보드·콘솔·네트워크를 검증하고 관련 테스트·정적 검사·빌드·리뷰·문서를 갱신한다.

## 합의 이력

- 2026-10-22: 사용자가 제안된 관리자 전용 서브관리자 영구 삭제 방식에 동의하고 추가를 요청했다. 기획 확정으로 기록하며 개발 전 작업계획 확인이 남아 있다.
