- 상태: 완료

- [확정 기획](../planning/admin-auth.md) · [작업계획·검증 기록](../plans/admin-auth.md) · [ERD](../architecture/erd.md)

## 화면과 사용자 흐름

| 경로 | 동작 |
|---|---|
| /login | 이메일·비밀번호 로그인. 공개 회원가입 없음 |
| / | 활성 직원용 대시보드. 최초·임시 비밀번호 계정은 /password로 이동 |
| /password | 현재 비밀번호를 확인하고 새 비밀번호로 변경. 강제 변경 상태에서는 업무 화면 접근 차단 |
| /admin/staff | 관리자 전용 직원 목록과 서브관리자 생성·이름 수정·활성 상태 변경·임시 비밀번호 재설정 |

로그인하지 않았거나 직원 프로필이 없거나 비활성 상태이면 업무 화면에 접근할 수 없다. 서브관리자에게 관리자 메뉴를 표시하지 않으며 URL 직접 접근도 대시보드로 돌려보낸다. API는 401/403으로 거부한다. 사용자 이름·권한·비밀번호 변경·로그아웃을 기존 차콜 공통 상단바 오른쪽에 표시한다.

## 계정과 비밀번호 정책

- 관리자가 서브관리자 이름·이메일·초기 비밀번호를 지정한다. 역할은 서버에서 sub_admin으로 고정한다.
- 최초 로그인·임시 비밀번호 로그인 후 변경 필수. 생성 화면과 목록에는 저장된 비밀번호를 표시하지 않는다. 관리자가 초기·임시 비밀번호를 별도로 전달한다.
- 새 비밀번호와 초기·임시 비밀번호는 영문·숫자를 포함한 8~16자다. 본인 변경 시 현재 비밀번호, 새 비밀번호 확인, 현재 비밀번호와 다름을 검증한다.
- 관리자 추가·승격·강등 및 관리자 영구 삭제 UI는 없다. 서브관리자 영구 삭제는 후속 삭제 기능에서 제공한다. 관리자의 상태 변경과 임시 비밀번호 재설정도 API에서 거부한다.
- 비활성화 상태에서는 기존 로그인 세션도 다음 업무 요청부터 차단한다. 재활성화는 세션을 영구 폐기하는 작업이 아니며 유효한 기존 세션이 다시 허용될 수 있다.
- 임시 비밀번호 재설정은 staff 상태를 먼저 갱신하여 기존 Auth 세션을 폐기하고 변경을 강제한 뒤 Auth 비밀번호를 변경한다. Auth 변경이 실패하면 기존 세션은 폐기된 상태로 남고 관리자가 재설정을 다시 수행해야 한다.
- 비밀번호 변경과 직원 상태 변경이 겹치면 updated_at 조건으로 변경 강제 상태를 함부로 해제하지 않는다. 부분 실패 시 새 비밀번호로 재로그인하거나 관리자에게 재설정을 요청한다.
- 로그아웃은 현재 세션(scope: local)을 종료한다. 다른 기기 세션을 일괄 종료하는 UI는 제공하지 않는다.

## Supabase 데이터와 권한

public.staff는 auth.users.id를 기본키·외래키로 참조한다. 필드는 name, role, is_active, must_change_password, credentials_reset_at, created_at, updated_at이다. 이메일·비밀번호는 Auth가 관리한다. members·상품·회원권·결제 테이블은 생성하지 않았다.

- anon은 staff 접근 권한이 없다.
- authenticated는 유효한 Auth 세션을 가진 활성 직원의 본인 행만 SELECT할 수 있다. 직접 INSERT/UPDATE/DELETE 권한은 없다.
- private.staff_session_valid()는 호출자 자신의 auth.uid()와 JWT session_id가 auth.sessions에 존재하는지 검사한다. 노출되지 않는 private 스키마의 제한된 SECURITY DEFINER 함수다.
- private.staff_revoke_reset_sessions()는 서버만 변경할 수 있는 credentials_reset_at 갱신 시 대상 auth.sessions를 삭제하는 트리거다. 일반 사용자에게 함수 실행 권한을 주지 않는다.
- 직원 목록·생성·수정은 요청마다 현재 활성 관리자임을 확인한 서버 전용 관리 클라이언트로 수행한다. 직원 목록의 이메일은 Auth 관리 API에서 읽는다.
- Auth 생성 뒤 staff 저장 실패 시 이번에 생성한 Auth 계정을 삭제하는 보상 처리를 수행한다. 정리까지 실패하면 운영자 확인이 필요한 오류로 처리한다.
- 각 POST/PATCH는 동일 Origin과 JSON 본문을 확인한다. 응답에는 private, no-store를 적용하고 인증 응답을 캐시하지 않는다.

## 운영과 초기 설정

루트 README의 환경 설정·첫 관리자 생성 절차를 따른다. 실제 관리자 이름·이메일·초기 비밀번호는 문서에 기록하지 않는다. 최초 로그인 정보는 Git 제외 `.env.admin-initial.local`에 소유자 읽기/쓰기 권한으로 저장한다. 비밀번호 변경 후 파일을 삭제한다.

첫 관리자 분실 시 Supabase 프로젝트 소유자가 Dashboard의 Auth 사용자 관리에서 해당 계정의 비밀번호를 재설정하고 로컬에서 다시 로그인한다. 이메일 발송 복구가 필요한 Dashboard 동작은 별도 SMTP 설정이 필요할 수 있으며 이번에는 구성·검증하지 않았다. 기존 관리자 추가·재설정 자동화는 제공하지 않는다.

## 검증과 제한

세부 명령·결과는 작업계획에 기록한다. 테스트용 Auth 계정만 생성·삭제했으며 첫 관리자 계정은 유지한다. 실제 Supabase 연결과 RLS·비활성화·세션 폐기·비밀번호 변경을 검증한다. Chromium의 PC·태블릿·모바일 크기와 인앱 브라우저 로그인 화면을 확인한다.

자연 만료까지 장시간 대기하는 세션 테스트, 동시 관리자 초기 생성 경쟁, Firefox·Safari·실물 모바일, SMTP·이메일 복구, 배포는 미검증이다. 직원 목록은 전체 조회와 직원별 Auth 조회로 구현하여 직원 수가 많아지면 페이지 나눔·조회 최적화가 필요하다. 개발용 ESLint 의존성의 기존 high 경고 5건은 별도 작업이다.

최종 검증: 2026-10-22 전체 26개 테스트(실제 Auth·DB·UI·보상 처리)와 린트·타입 검사·Webpack 빌드를 통과했다. SDK 로컬 세션 만료 시각을 앞당긴 실제 토큰 갱신도 확인했다. [권한·세션 결정 기록](../decisions/staff-auth-permissions.md)을 참고한다.

## 로그인 UI 보정 (2026-10-22)

사용자 요청으로 이메일·비밀번호 입력을 sm 기반·40px 높이·8px 반경·14px 글꼴과 동일 포커스 표시로 통일했다. 비밀번호 눈 아이콘은 16px이며 입력 오른쪽 가운데에 배치한다. `.form > button`으로 정렬 범위를 제한해 내부 눈 버튼이 위로 치우치는 문제를 해결했다. 로그인 제출 버튼은 폼 전체 너비로 표시한다. 후속 사용자 요청으로 높이를 40px로 변경하고 필드와의 간격을 24px로 확대했다. 입력 포커스 외곽선은 제거하고 테두리 색만 유지한다.

1440·768·390px에서 두 입력 크기·버튼 너비·아이콘 중심과 비밀번호 보기/숨기기·값 유지를 자동 검증했다. 관련 인증 테스트 5개(18.7초), 린트·타입 검사·Webpack 빌드 통과. 인앱 브라우저에서도 정렬과 버튼을 시각 확인했다. 기능·권한 변경 없음, 사용자 확인 대기·커밋 전이다.

후속 보정 검증: 입력 outline 없음·버튼 높이 40px·필드와 최소 24px 간격을 세 화면 크기에서 확인했다. 관련 테스트 4개(6.6초), 린트·타입·Webpack 빌드 통과. 인앱 브라우저 시각 검토와 CSS 범위·키보드 토글·로딩 상태 리뷰를 마쳤다. 사용자 확인 대기이며 커밋하지 않았다.


## 비밀번호 규칙·변경 UI 후속 보정 (2026-10-22)

새 비밀번호·서브관리자 초기/임시 비밀번호는 영문·숫자를 포함한 8~16자다. 기존 계정의 로그인과 현재 비밀번호 확인은 이전에 발급한 긴 비밀번호를 사용할 수 있도록 최대 128자를 유지한다. 기존 계정을 자동 재설정하지 않았다. 앞으로 bootstrap-admin이 생성하는 초기 비밀번호는 15자다.

비밀번호 변경의 세 입력과 눈 아이콘은 로그인과 같은 스타일을 재사용한다. 입력 40px·8px 반경·14px 글꼴, 입력 포커스 외곽선 없음·브랜드색 테두리, 16px 눈 아이콘 수직 중앙, 변경 버튼 전체 너비·40px 높이·마지막 필드와 24px 간격을 적용했다.

검증: 전체 32개 테스트 통과 후 변경 폼의 세 화면 크기 정렬·포커스 검증을 추가해 관련 테스트도 재통과했다. 린트·타입·Webpack 빌드 통과, 모바일 변경 화면 시각 검토·코드 리뷰 완료. 사용자 확인 대기다.


## 관리자 관리 UI 개선 (2026-10-22)

- `/admin/staff`는 직원 목록 중심이다. 목록 제목 오른쪽 새로고침·서브관리자 생성 버튼은 좁은 화면에서 줄바꿈한다.
- 생성 버튼은 이름·이메일·초기 비밀번호와 정책 안내를 담은 모달을 연다. 취소 후 다시 열면 빈 폼이며 생성 성공 시 닫고 목록·성공 메시지를 갱신한다. 생성 실패 시 입력을 유지하고 모달 안에 오류를 표시한다.
- 서브관리자 행은 대상 이름을 포함한 접근성 이름의 더보기 버튼 하나를 제공한다. Mantine Menu의 이름 수정·비활성화/재활성화·비밀번호 재설정 항목은 기존 편집·확인 모달로 연결된다. 관리자 행은 관리 동작이 없다.
- 메뉴는 portal로 렌더링되어 표 스크롤 영역에 잘리지 않는다. Escape·바깥 클릭·키보드 선택과 포커스 복귀를 지원한다. 처리 중에는 모달 취소·닫기·Escape·바깥 클릭 및 중복 제출을 막는다.
- 목록 조회 오류와 폼 오류를 분리한다. 편집 실패도 해당 모달 안에 표시하며 값을 유지한다.
- 모든 폼 입력과 실행·취소 버튼 높이는 공통 변수 기반 40px다. 기존 로그인·비밀번호 입력 36px 기준을 대체하며 기존 전체 너비 제출·24px 간격·포커스 정책은 유지한다.
- 관련 소스: `src/components/staff/staff-manager.tsx`, `staff.module.css`, `src/components/auth/auth.module.css`, `src/app/globals.css`. 인증·권한·API·데이터 정책은 기존과 같다.
- 기획·검증 기록: [기획](../planning/staff-ui.md), [작업계획](../plans/staff-ui.md). 별도 서브관리자 삭제 작업은 이번 구현에 포함하지 않는다.

## 서브관리자 영구 삭제 (2026-10-22)

[삭제 기획](../planning/staff-delete.md)·[작업계획](../plans/staff-delete.md)에 따라 관리자 관리의 서브관리자 행 더보기 메뉴에 삭제를 추가했다. 확인창에 대상 이름·이메일과 영구 삭제·복구 불가·세션 종료 안내를 표시한다. 취소·닫기는 변경하지 않으며 처리 중 취소·닫기·중복 제출을 막는다.

DELETE /api/staff/[id]는 동일 Origin·JSON, 현재 활성 관리자·비밀번호 변경 완료, 유효 ID·본인 아님·대상 sub_admin을 검증한다. 대상의 is_active=false와 credentials_reset_at을 먼저 갱신하여 기존 세션을 차단한 뒤 서버 Auth Admin deleteUser(id, false)를 호출한다. 현재 FK의 ON DELETE CASCADE로 staff도 삭제되며 새 DB 스키마는 추가하지 않았다. 관리자 계정·본인은 삭제할 수 없다. 비활성 서브관리자도 삭제할 수 있다.

세션 차단에 실패하면 Auth 삭제로 진행하지 않는다. Auth 삭제 완료를 확인할 수 없으면 접근을 먼저 차단했음을 안내하고 목록 확인·삭제 재시도·재활성화를 안내한다. 삭제 성공 후 목록 조회만 실패하면 대상 행을 로컬 목록에서 제거하고 삭제 성공과 갱신 실패를 구분해 표시한다.

관련 코드: src/lib/auth/delete-staff.ts(단계별 실패 처리), src/app/api/staff/[id]/route.ts(DELETE 권한·대상 검증), src/components/staff/staff-manager.tsx(삭제 메뉴·확인창·결과), tests/staff-delete.spec.ts(실제 테스트 계정 삭제·권한·세션·오류·반응형 검증).

기존 ‘영구 삭제 UI 없음’ 정책은 이 후속 요청으로 서브관리자에 한해 변경됐다. 관리자 영구 삭제와 복구 기능은 제공하지 않는다. 회원·상담 데이터는 아직 없으며 추후 직원 참조 FK를 추가할 때 업무 이력 보존 정책을 검토한다.

후속 UI 보정: 직원 행 더보기는 32px 아이콘 버튼 안의 16px 점 세 개로 표시하며 툴팁·대상별 접근성 이름을 유지한다. 공통 상단바 계정 이름 링크에서 비밀번호 변경에 접근하고 오른쪽 로그아웃을 사용한다. 내부 화면 헤더의 중복 계정 영역·우측 GitHub/WORKSPACE 장식은 제거했다.

삭제 검증 결과: 실제 활성·비활성 테스트 계정의 Auth·staff 제거, 비로그인·서브관리자·본인·관리자 대상 보호, 기존 토큰·재로그인 차단, 실패 단계·목록 갱신 실패·취소 포커스·중복 제출을 확인했다. 47개 회귀 시나리오는 전체 실행 44개와 남은 상단바 3개 재실행으로 검증 완료했다. 린트·타입 검사·Webpack 빌드 통과. 삭제 테스트 계정 잔여 0명, 사용자 확인 대기·커밋 전이다.


## 로딩·권한 배지·상태 토글·성공 토스트 (2026-10-22)

- 목록 최초 조회는 스켈레톤과 읽는 중 안내를 표시한다. 재조회는 기존 행을 유지하고 새로고침 아이콘 로딩·목록 aria-busy·갱신 중 안내를 표시한다. 조회 중 변경과 중복 재조회를 막는다. 최초 조회 실패를 빈 목록과 구분하고 아이콘 버튼으로 재시도한다.
- 목록 새로고침은 16px 아이콘/32px 버튼과 툴팁·접근성 이름을 사용한다. 권한은 공통 `RoleBadge`로 관리자(연한 오렌지)·서브관리자(중립 회색)를 구분한다. 공통 상단바 권한도 같은 배지를 사용하며 모바일 숨김 기준을 유지한다.
- 상태 컬럼은 서브관리자만 활성/비활성 텍스트와 Switch를 제공한다. 별도 확인 모달 없이 기존 PATCH `/api/staff/[id]`에 `action=status`, 목표 `is_active`를 전송한다. 서버 성공 후 로컬 행을 반영하고 목록을 재조회한다. 관리자 행은 상태 텍스트만 표시한다.
- 상태 요청 중 토글과 충돌하는 목록 조작을 막고 해당 행 스피너를 표시한다. 요청 실패는 기존 값을 유지하고 행 안에 오류·토글 재시도 안내를 표시한다. 상태 변경 성공 뒤 목록 재조회 실패는 변경 성공과 구분해 안내한다. 더보기의 중복 상태 항목은 제거했으며 이름 수정·재설정·삭제는 유지한다.
- 생성·수정·상태 변경·재설정·삭제 성공 안내는 목록 위 문구 대신 `SuccessToast`를 portal로 화면 우측 하단(오른쪽·아래 16px)에 표시한다. 5초 후 닫히며 마우스 hover 중 타이머를 멈추고 벗어나면 5초를 다시 센다. 닫기 버튼 없이 role=status를 제공하고 390px에서도 화면 안에 표시한다. 오류 안내는 해당 목록·행·모달에 유지한다.
- 코드: `src/components/staff/staff-manager.tsx`, `staff.module.css`, `src/components/common/role-badge.tsx`, `success-toast.tsx`와 각 CSS. 신규 의존성·서버 권한·데이터 정책 변경 없음.
- 상세 승인·검증: [기획](../planning/loading-staff-controls.md), [작업계획](../plans/loading-staff-controls.md).

토스트 후속 보정: 오른쪽·아래 16px 우측 하단 정렬·닫기 버튼 없음, 성공 문구는 “계정 생성 완료/이름 변경 완료/비밀번호 재설정 완료/활성화 완료/비활성화 완료/계정 삭제 완료”로 짧게 표시한다. 사용자 이름을 제외해 긴 이름에도 한 줄을 유지한다. 서버 응답·업무 정책·오류 안내는 변경하지 않는다.

토스트 최소 너비 보정: `success-toast.module.css`의 min-width를 min(240px, 화면 너비-32px)로 설정해 짧은 성공 문구에도 여유를 제공한다. 우측 하단·한 줄·자동 닫기 동작은 유지한다.

## 강사 표시와 수업 연동 (2026-10-22)

[그룹수업 시간표](class-schedule.md)를 위해 직원 관리에 다음을 추가했다.

- 직원 목록에 '강사' 열이 생겼다. 관리자는 더보기 메뉴의 '강사 지정/해제'로 관리자 본인·다른 관리자·서브관리자 모두의 강사 여부(`staff.is_instructor`)를 바꿀 수 있다. 강사 여부는 권한과 무관하다. 관리자 행의 더보기에는 이 항목만 있고, 서브관리자 행에서는 '비밀번호 재설정'과 삭제 구분선 사이에 있다.
- `PATCH /api/staff/[id]` `action: instructor`는 관리자만 쓸 수 있고, 역할 제한(`role=sub_admin`)을 적용하지 않는 유일한 변경이다. 다른 변경은 지금처럼 서브관리자에게만 적용된다.
- `GET /api/staff`는 직원마다 앞으로 맡은 회차 수(`upcoming_sessions`)를 함께 돌려준다. 회차가 있는 직원을 강사 해제하거나 비활성화하려 하면 확인 Modal을 띄우고, 삭제 Modal에도 같은 경고를 표시한다. 진행하면 staff 트리거가 앞으로의 회차를 '강사 미정'으로 바꾼다.
- 직원 목록을 불러오는 도중 삭제된 계정(Auth 404)은 목록 전체를 실패시키지 않고 목록에서 뺀다.
