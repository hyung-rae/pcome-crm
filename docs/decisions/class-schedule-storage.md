# 반복 수업 저장과 강사 겹침 보장

- 상태: 적용
- 최종 갱신: 2026-10-22
- 관련 문서: [확정 기획](../planning/class-schedule.md), [실제 기능](../features/class-schedule.md), [작업계획](../plans/class-schedule.md)

## 배경

기획은 무기한 반복 수업, 회차별 수정·휴강·삭제, '이후 전체' 변경, 같은 강사의 시간 겹침 차단(반복 수업은 하루라도 겹치면 전체 차단)을 요구한다. 반복 규칙만 저장하고 조회할 때 계산하면 저장은 가볍다. 하지만 회차별 예외 기록, 무기한 규칙끼리의 겹침 판단, 동시 요청 처리를 모두 앱 코드로 해결해야 한다.

## 결정

- 반복 규칙(`class_series`)과 회차(`class_sessions`)를 따로 저장하고, 회차는 오늘부터 1년 앞까지 미리 만든다. 사용자와 1년 범위를 합의했다.
- 강사 겹침은 회차 테이블의 제외 제약(`btree_gist`, 같은 강사 + `[시작, 종료)` 범위 겹침, 정상·강사 지정 회차만)으로 보장한다.
- 스케줄러(pg_cron)는 쓰지 않는다. 모든 시간표 API가 시작할 때 확장 함수를 호출해 범위를 채운다. 쓰기는 오늘+1년 이내 날짜만 허용한다. 그래서 쓰기 시점에는 모든 반복이 범위 끝까지 채워져 있고, 범위 밖에 나중에 생길 회차와 겹칠 수 없다.
- 등록·수정·휴강·삭제는 각각 Postgres 함수 하나에서 lock → 확장 → 검증 → 겹침 목록 조회 → 저장 순서로 처리한다. 함수는 `service_role`만 실행하며 서버 API의 권한 확인 뒤에 호출한다.
- 반복 회차 삭제는 '삭제됨' 상태로 남긴다. 확장이나 '이후 전체' 변경 때 지운 날짜가 다시 생기지 않게 하기 위해서다. '이후 전체' 변경은 규칙을 나눠, 이전 규칙과 지난 회차를 보존한다.
- 강사 해제·비활성화는 staff 트리거가 앞으로의 회차 강사를 비운다. 서브관리자 삭제 흐름이 Auth 삭제 전에 먼저 비활성화하므로, 트리거 하나로 세 경우를 모두 처리한다.

## 영향과 제한

- 규칙 하나당 최대 약 1년치 회차가 저장된다(주 2회면 약 104행). 단일 지점 규모에서는 문제없지만, 규모가 커지면 범위·인덱스를 다시 검토한다.
- 1년 범위 확장은 API가 호출될 때 일어나므로, 오래 사용하지 않으면 다음 요청이 그만큼 더 일한다.
- 쓰기는 advisory lock 하나로 직렬화된다. 동시 사용자가 많아지면 강사별 lock 등으로 나누는 것을 검토한다.
- 앱 SQL은 원격 적용 전에 PGlite(WASM Postgres)와 Auth 스텁으로 정책 테스트를 거쳤다. 실제 원격 동작은 E2E로 확인한다.
