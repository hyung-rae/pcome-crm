# 직원 권한과 세션 검증

- 상태: 적용
- 최종 갱신: 2026-10-22
- 관련 문서: [확정 기획](../planning/admin-auth.md), [실제 기능](../features/admin-auth.md)

## 배경

활성 관리자·서브관리자만 CRM에 접근하며, 비활성화나 임시 비밀번호 재설정 후 기존 로그인도 다음 요청에서 차단해야 한다. 브라우저 메뉴나 갱신 전 JWT의 역할만 확인해서는 변경된 권한을 반영할 수 없다.

## 결정

- auth.users는 이메일·비밀번호를 관리하고 public.staff가 직원 이름·현재 역할·활성 상태·비밀번호 변경 강제를 관리한다. 사용자 편집 가능 user_metadata는 권한 근거로 쓰지 않는다.
- 앱의 Auth 처리는 요청별 서버 SSR 클라이언트를 이용하고 브라우저는 동일 Origin 앱 API를 호출한다. Proxy는 쿠키 갱신만 담당하며 각 화면·API에서 getUser와 직원 DB 상태를 검증한다.
- 일반 직원 DB 권한은 유효 세션을 가진 활성 직원의 자기 행 SELECT로 제한한다. 관리자 직원 목록·변경은 서버에서 현재 관리자 여부를 확인한 뒤 서버 전용 관리 키로 수행한다.
- 세션 유효성 검사와 임시 비밀번호 재설정 세션 폐기에는 auth.sessions 접근이 필요하므로 private 스키마의 제한된 SECURITY DEFINER 헬퍼·트리거를 사용한다. 본인 검사 함수는 auth.uid() 확인과 본인 session_id 비교만 수행하며 임의 사용자 ID를 받지 않는다. 세션 삭제 트리거 함수는 일반 사용자 실행 권한이 없고 staff 변경 권한도 서버에만 있다.
- Auth·staff 생성은 한 DB 트랜잭션으로 묶이지 않으므로 프로필 저장 실패 시 새 Auth 계정만 보상 삭제한다. 보상 실패는 운영 정리 오류로 노출한다.

## 영향과 제한

보호 요청마다 Auth·DB 왕복이 필요하지만 역할·활성 상태 변경과 세션 폐기를 다음 요청부터 반영한다. 이미 화면에 표시한 데이터나 변경 전에 시작된 요청을 원격으로 취소하지 않는다. 직원 목록은 현재 소규모 단일 지점을 기준으로 하며 규모가 커지면 조회 최적화를 검토한다.
