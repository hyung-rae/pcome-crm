# UI 공통 가이드

- 상태: 적용 기준 확정
- 최종 갱신: 2026-10-22
- 근거: 사용자가 현재 대시보드의 테마 색·크기·모양을 이후 UI의 공통 기준으로 지정함
- 관련 문서: [대시보드 기능](../features/dashboard-ui.md), [시스템 구조](system.md)

## 적용 원칙

새 화면도 현재 대시보드와 같은 제품으로 느껴지도록 구현한다. Mantine과 기존 테마·레이아웃을 우선 재사용하고 작은 패딩, 얇은 테두리, 절제된 그림자, 일관된 아이콘을 사용한다. 공통 스타일 변경은 사용자와 합의하고 이 문서·영향받는 화면을 함께 갱신한다.

현재 기준 소스는 `src/theme.ts`, `src/components/dashboard/dashboard.tsx`, `src/components/dashboard/dashboard.module.css`다. 아래 값은 현재 구현과 대조했다. CSS Modules 값이 자동으로 모든 Mantine 컴포넌트에 적용되는 것은 아니므로 새 컴포넌트에서도 해당 크기와 상태 스타일을 명시한다. 같은 패턴이 반복되면 공통 컴포넌트로 추출해 재사용한다.

버튼을 불필요하게 크게 만들지 않는다. 장식용 아이콘과 클릭 가능한 아이콘의 크기는 구분하고, 시각적 크기를 줄여도 조작 영역·가독성·키보드 접근성을 유지한다. 아직 구현하지 않은 입력 폼·표·새 버튼 종류는 가까운 기존 패턴에 맞추되 새 공통 수치를 이미 구현된 기준으로 단정하지 않는다.

## 레이아웃·반응형

공통 상단바와 LNB는 같은 `#1D1D1D` 배경으로 연결하며 두 영역 사이의 구분선을 두지 않는다.

- LNB와 메인 화면을 외부 여백·테두리·바깥 반경 없이 전체 화면을 채우는 차콜 앱 프레임으로 감싼다.
- 프레임은 화면 높이에 맞추고 본문만 내부 스크롤한다. 상단바·LNB는 브라우저가 아닌 프레임을 배치 기준으로 삼는다.
- 공통 상단바는 높이 48px이며, PC 접기·펼치기 및 모바일 메뉴 버튼을 고정 위치에 제공한다. PC LNB는 248px / 접힘 88px.
- 992px 미만에서는 PC LNB 대신 280px Drawer를 사용한다. 576px 미만에서는 모바일 간격을 적용한다.
- 내부 화면 상단바(브레드크럼)는 없다. 본문 영역 확보를 위해 2026-10-22 사용자 요청으로 제거했으며 본문은 공통 상단바 바로 아래에서 시작한다.
- 본문 패딩: PC 24px 24px 24px, 태블릿 20px 20px 24px, 모바일 16px 16px 24px. 2026-10-22 사용자 요청으로 기존(PC 48px 44px 24px, 태블릿 36px 28px 24px, 모바일 30px 20px 24px)의 절반 정도로 줄였다.
- 화면마다 별도의 사이드바·상단바를 복제하지 않고 기존 공통 레이아웃을 재사용한다.

## 상태·전환·검증

- LNB 너비·본문 위치·토글 회전: 200ms ease. `prefers-reduced-motion: reduce`에서는 전환하지 않는다.
- 아이콘 전용 버튼은 접근성 이름을 제공하며 툴팁으로 의미를 보완한다. 활성 메뉴는 시각적 표시와 `aria-current`를 제공한다.
- 키보드 포커스는 3px 주 조작색 외곽선과 4px 간격으로 표시한다. Drawer portal에도 색상 변수·포커스 스타일을 적용한다.
- 준비 중 동작은 비활성 표시로 구분한다. 데이터가 없으면 실제 빈 상태를 표시한다.
- 수정 시 기본·hover·active·focus·disabled, 접힘·펼침, 1440·768·390px 화면을 관련 범위에 맞춰 검증한다. 콘솔·네트워크 오류와 기존 메뉴 동작도 확인한다.

## 기록

2026-10-22 현재 소스와 문서 대조 후 작성했다. 이번 작업은 지침·문서 변경만 포함하며 런타임 UI는 변경하지 않았다. 문서 링크와 diff를 검토했고, 공통 토큰 추출이나 신규 컴포넌트 구현은 수행하지 않았다.

LNB 여백: PC 상하 20px·좌우 16px, 로고와 메뉴 영역 간격 24px. 접힌 LNB도 같은 상단 패딩과 24px 메뉴 간격을 사용한다. 모바일 Drawer의 별도 간격은 유지한다.

## 직원 인증 화면 패턴 (2026-10-22)

로그인·비밀번호 화면은 차콜 전체 배경에 흰 카드(최대 400px, 비밀번호 460px, 12px 반경)를 배치한다. 기존 오렌지 조작색·xs 버튼·13px 설명을 유지한다. 입력은 Mantine 기본 입력을 사용한다. 직원 목록은 흰 패널과 얇은 행 경계선을 사용하며 좁은 화면에서는 표 영역만 가로 스크롤한다. 서브관리자 생성 폼은 모바일에서 세로로 배치한다. 직원 계정 조작은 높이 48px인 차콜 공통 상단바 오른쪽에 배치한다. 내부 화면 헤더(브레드크럼)는 이후 제거했다.

로그인 입력은 40px 높이·8px 반경·14px 글꼴로 통일하며, 사용자 요청으로 입력 포커스 외곽선은 제거하고 테두리 색상만 브랜드색으로 표시한다. 비밀번호 표시 아이콘은 16px·오른쪽 수직 중앙이다. 로그인 버튼은 사용자 지정에 따라 전체 너비·40px 높이·14px 글꼴이며, 필드와의 간격은 기본 16px에 상단 마진 8px를 더해 24px다. 폼 버튼 정렬은 내부 조작 버튼에 영향을 주지 않도록 직계 자식에만 적용한다.

비밀번호 변경 화면도 위 로그인 입력·눈 아이콘·버튼 스타일을 그대로 재사용한다. 세 입력은 40px, 변경 버튼은 전체 너비·40px·위 간격 24px이며 입력 포커스 외곽선은 없다.


## 폼 조작부 크기 일치 (2026-10-22 사용자 확정)

기존 인증 화면의 입력 36px·제출 40px 기준은 아래 기준으로 대체한다.

- 로그인·비밀번호 변경·직원 생성·편집 입력과 폼 실행·취소 버튼은 모두 40px 높이로 통일한다. 공통 CSS 변수 `--crm-form-control-height`는 `src/app/globals.css`에서 정의한다.
- 같은 줄에 입력과 버튼을 배치하면 라벨·도움말을 제외한 조작부의 위·아래 경계를 맞춘다. 다른 Mantine size의 기본값을 혼용하지 않는다.
- 폼 버튼은 기존 오렌지·작은 좌우 패딩을 유지한다. 표·헤더의 독립 조작 및 아이콘 버튼은 기존 크기 기준을 따른다.
- 앞으로 폼 UI 변경 시 입력·버튼의 실제 높이와 정렬을 1440·768·390px에서 확인한다. 기본·로딩·비활성·오류 상태에서도 크기와 배치를 유지하며 비밀번호 내부 표시 버튼까지 확대하지 않는다.
- 관리자 관리는 목록 상단 도구 모음, 생성 버튼→세로 입력 모달, 행별 더보기→Menu 팝오버→편집 모달 패턴을 사용한다. Menu는 portal로 표시하고 키보드·Escape·바깥 클릭을 지원한다. 모달 오류는 모달 내부에 표시한다.


## 상단바 계정·행별 아이콘 조작 (2026-10-22)

- 오른쪽 WORKSPACE 문구와 GitHub 링크는 제거한다. 왼쪽 제품 이름은 유지한다.
- 차콜 공통 상단바 오른쪽에 16px 사용자 아이콘·이름·권한·로그아웃을 배치한다. 이름 링크는 기존 비밀번호 변경 화면으로 연결되며 접근성 이름·툴팁에 전체 이름·권한·동작을 제공한다. 내부 화면 헤더에 계정 UI를 중복 표시하지 않는다.
- 상단바는 48px 유지. 긴 이름은 말줄임하고 모바일에서는 권한 텍스트만 숨겨 계정·로그아웃·메뉴 조작의 겹침을 막는다. 링크와 로그아웃은 차콜 위 기본·hover·active·focus 대비를 유지한다.
- 로그아웃 실패는 상단바 아래 오류 안내로 표시하며 조작 영역 높이를 바꾸지 않는다. 재시도할 수 있고 처리 중 중복 제출을 막는다.
- 직원 행 더보기는 16px 가로 점 세 개 아이콘·32px 정사각형 조작 영역·대상 이름을 포함한 접근성 이름·더보기 툴팁을 사용한다. 텍스트 버튼을 추가로 표시하지 않는다.


## 로딩·배지·토글·토스트 패턴 (2026-10-22)

- 페이지 이동은 기존 화면을 유지하고 별도 스피너·문구·필터를 표시하지 않는다. 초기 목록은 스켈레톤, 갱신은 기존 행 유지·아이콘 로딩·aria-busy를 사용한다. 조회 실패와 빈 상태를 구분한다.
- 관리자/서브관리자 권한은 11px·3px 7px 패딩·5px 반경 배지를 공통으로 사용한다. 관리자 `#FFF0EB`/`#A82E18`, 서브관리자 `#F0F0F2`/`#565656`. 텍스트를 포함해 색에만 의존하지 않는다.
- 상태 Switch는 활성/비활성 텍스트·대상별 접근성 이름·키보드 조작·처리 중 잠금·행 스피너를 제공한다. 관리자 행에 토글을 제공하지 않는다.
- 성공 toast는 오른쪽 16px·아래 16px, 최소 240px(좁은 화면은 화면 너비-32px), 최대 420px/화면 너비-32px, 흰 배경·얇은 테두리·오렌지 포인트·13px 텍스트다. 16px 아이콘을 사용하고 닫기 버튼은 표시하지 않는다. 문서 레이아웃을 밀지 않는 portal로 표시한다.
- 성공 toast는 5초 후 자동으로 닫히며 마우스 hover 중 유지한다. role=status로 안내한다. 재시도에 필요한 오류는 기존 문맥 안에 유지한다.
- 동작 줄이기 설정에서 스피너·스켈레톤 애니메이션을 멈춘다.

토스트 문구는 한 줄로 읽을 수 있는 핵심 결과만 표시한다: 계정 생성 완료, 이름 변경 완료, 비밀번호 재설정 완료, 활성화 완료, 비활성화 완료, 계정 삭제 완료. 사용자 이름·장문의 부가 설명은 성공 토스트에 넣지 않는다. 실제 업무 정책·오류 복구 안내는 관련 화면에 유지한다.
