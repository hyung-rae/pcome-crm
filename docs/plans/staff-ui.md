## 구현 순서

1. 직원 생성 모달 및 목록 도구 모음, 행별 Mantine Menu 구현.
2. 생성·편집 오류 상태 분리, 처리 중 닫기 차단, 입력·폼 버튼 40px 통일.
3. 기존 인증 E2E 갱신 및 반응형·키보드·취소·API 실패·중복 제출 테스트 추가.
4. 린트·타입·Webpack 빌드 및 전체 테스트 실행.
5. 실제 Chromium 1440·768·390px 사용자 흐름·예외·콘솔·실패 요청·캡처 확인.
6. 코드 리뷰·문서 갱신 후 사용자 확인 대기. 커밋은 최종 확인 후.

## 검증 시나리오

- 성공: 생성 모달 열기→유효값 입력→생성→닫기·목록 갱신. 더보기에서 올바른 대상 이름 수정·상태 변경·재설정. 입력·버튼 모두 40px.
- 실패: 필수 입력 검증, 생성·수정 API 오류 시 값 유지·모달 오류, 처리 중 닫기·중복 제출 차단.
- 취소·접근성: 취소 후 빈 생성 폼, Escape·바깥 클릭·키보드 메뉴 선택·포커스 복귀.
- 반응형: 1440·768·390px 모달·메뉴 경계 및 테이블 스크롤, 로그인·비밀번호·기존 메뉴 회귀.
- 명령: npm run lint / npm run typecheck / npm run build -- --webpack / PLAYWRIGHT_BASE_URL=http://localhost:3002 npm run test:e2e / git diff --check.
- 도구: 기존 Playwright, 신규 도구 없음. 생략 없음.

## 결과·리뷰·문서

- 전체 `npm run test:e2e`: 35개 통과(48.3초). 실제 생성·수정·비활성·재활성·재설정과 인증·대시보드 회귀 포함.
- 콘솔 및 메뉴 전환 완료 검증 추가 후 `npm run test:e2e -- tests/staff-ui.spec.ts`: 3개 통과(15.1초).
- `npm run lint`, `npm run typecheck`, `npm run build -- --webpack`, `git diff --check`: 통과. 신규 의존성 없음.
- 실제 Chromium `http://localhost:8888`에서 1440·768·390px 생성 모달·더보기·키보드·오류·취소·처리 중 Escape 차단·40px 기하 검증. 캡처 `test-results/staff-create-{width}.png`, `staff-menu-{width}.png`를 생성하고 모바일·PC·태블릿을 시각 검토했다. 팝오버는 테이블 영역 밖에서도 잘리지 않고 모바일 문서 가로 넘침이 없다.
- 생성·수정 실패는 테스트에서 의도한 503 응답이다. 이 예상 HTTP 콘솔 메시지를 제외한 console.error·pageerror·실패 요청은 없었다. 실제 성공 경로는 기존 인증 테스트로 확인했다.
- 초기 샌드박스 실행은 포트 EPERM으로 실패해 승인된 실행으로 재검증했다. 첫 전체 실행은 개발 중 소스 변경에 따른 HMR 재탐색과 메뉴 포커스 이동 전 키 입력으로 실패했다. 소스 변경 없이 재실행하고 메뉴 자동 포커스 완료를 기다리도록 테스트를 보완하여 모두 통과했다.
- 개발 후 리뷰: 현재 소스·테스트·확정 기획을 대조했다. 대상별 메뉴·폼 오류 분리·실패 값 유지·모달 닫기 방지·portal·40px 공통 변수·내부 눈 버튼 크기·권한/API 비변경을 확인했다. 미해결 중대 문제 없음.
- UI 가이드·기능 문서·시스템 구조·색인·현황 갱신. 삭제 후속 작업의 진입점 문구도 더보기 메뉴로 연계했다.
- 미검증: Firefox·Safari·실물 기기·배포. 테스트·리뷰 생략 없음.
- 사용자 최종 확인: 대기. 커밋하지 않음. 커밋 직전 리뷰는 최종 확인 후 수행.

## 헤더·더보기 후속 UI 보정 (2026-10-22)

- 사용자 지시: 더보기를 아이콘 버튼으로 교체, 공통 상단바 오른쪽 GitHub 링크·WORKSPACE 텍스트 제거, 로그인 계정 UI·로그아웃 배치.
- 기존 기능의 표시·배치만 바꾸는 작은 수정으로 기존 계획에 기록한다. 새로운 인증·권한·데이터 정책 없음.
- 구현: 더보기 16px 가로 점 아이콘·32px 조작 영역·대상별 접근성 이름·툴팁. 계정 이름·권한 및 비밀번호 변경 링크·로그아웃을 차콜 공통 상단바 오른쪽으로 이동하고 내부 화면 헤더의 중복 계정 영역 제거. 모바일 이름 말줄임 및 권한 표시 축약, 이름 링크로 기존 비밀번호 변경 접근 유지.
- 검증: 세 화면 크기에서 상단바 48px·좌우 조작 충돌 없음·계정 중복 없음·GitHub/WORKSPACE 우측 장식 제거·더보기 아이콘/툴팁·메뉴 키보드 동작, 로그아웃 실패/재시도와 실제 로그아웃·인증 회귀. 기존 Playwright 테스트 갱신 및 관련 테스트 추가, 린트·타입·빌드·실제 브라우저·리뷰·문서 갱신. 생략 없음.
- 상태: 진행 중, 사용자 최종 확인 후 커밋.

### 헤더·아이콘 보정 검증·리뷰 결과

- `npm run lint`, `npm run typecheck`, `npm run build -- --webpack`: 통과. `git diff --check` 확인.
- 현재 공유 폴더에는 별도 직원 삭제 구현이 함께 존재한다. 해당 기능과 메뉴 참조·포커스 처리를 유지했다.
- 공유 테스트 세션 파일 정리 충돌로 초기 실행이 실패해 테스트 파일·세션을 임시 디렉터리 `pcome-ui-verify-ed78yc8b`로 분리하고 실제 앱 `http://localhost:8888`에 연결했다. 원래 테스트 파일과 최종 분리 사본은 동일하다.
- 분리 실행 전체 47개 중 46개 통과(56.7초). 나머지 1개는 로그아웃 성공 뒤 기존 replace+refresh가 취소한 로그인 RSC 요청을 실패로 집계했다. 정상 취소 `net::ERR_ABORTED`와 `/login` 경로만 예외로 구분한 뒤 상단바 3개 테스트 모두 통과(9.9초). 앱 인증 흐름은 변경하지 않았다.
- 1440·768·390px 상단바 48px, 제품명·계정·로그아웃 경계, 계정 중복 없음, GitHub 링크·우측 WORKSPACE 제거, 실패 안내·재시도·실제 로그아웃을 Chromium에서 검증했다. `account-header-{width}.png`, `account-error-{width}.png` 캡처를 시각 검토했다.
- 더보기는 ActionIcon 32px·SVG 16px이며 대상별 접근성 이름·툴팁과 기존 메뉴 항목·키보드 처리를 유지한다. Tooltip은 Menu.Target 안에서 실제 아이콘 버튼을 감싼다.
- React best practices 스킬 기준으로 컴포넌트 역할·훅·이벤트·접근성·선택적 스타일 props·기존 비밀번호 화면 영향·서버 권한 비변경을 리뷰했다. 로그아웃 오류는 헤더 높이를 늘리지 않고 접근 가능한 alert로 표시한다. 미해결 중대 문제 없음.
- UI 가이드·대시보드 및 인증 기능 문서·시스템 구조에 실제 배치·경로를 반영했다. Firefox·Safari·실물 기기·배포는 미검증. 생략 없음.
- 사용자 최종 확인 대기. 커밋하지 않음. 커밋 직전 리뷰는 사용자 최종 확인 후 수행한다.

- 최종 더보기 UI 테스트: 3개 통과(10.9초). 390px 아이콘 버튼·메뉴 portal 캡처 시각 확인. 임시 복사한 환경 파일은 검증 후 삭제했다.


## 사용자 승인 및 커밋 직전 최종 리뷰 (2026-10-22)

- 사용자의 “커밋해줘” 지시를 최종 승인 및 커밋 권한으로 기록했다. 이전 확인 대기 기록은 작업 당시 이력이다.

- 최종 UI: 생성 모달·더보기 아이콘·권한 배지·상태 컬럼 토글·로딩, 우측 하단 토스트(최소 240px·짧은 한 줄·닫기 버튼 없음·5초 자동 닫기)를 포함한다.

- 완료 처리. 커밋 직후 리뷰한 파일 목록과 커밋 tree 및 작업 폴더 상태를 확인한다. 배포·원격 push는 이번 요청에 포함하지 않는다.
