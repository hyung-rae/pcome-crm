- 확정 기획: [기획](../planning/dashboard-charts.md)

## 현재 요약

사용자가 기획을 확정하고 작업계획 작성과 개발 시작을 함께 지시했다(2026-10-22). 대시보드의 빈 '워크스페이스 현황' 패널을 '이번 주 수업 현황'으로 바꾸고, 기존 회차 조회 API로 이번 주 요일별·강사별 수업 수를 쌓은 막대 차트 2개로 보여준다. DB·API 변경은 없고 `@mantine/charts`·`recharts` 의존성을 추가한다.

## 구현 방향 및 영향 범위

| 영역 | 변경 |
|---|---|
| 의존성 | `@mantine/charts@^9.7.3`(Mantine core와 같은 버전), peer `recharts@^3`. `src/app/layout.tsx`에 `@mantine/charts/styles.css` 추가 |
| 집계 | `src/lib/classes/stats.ts`(순수 함수): 요일별 정상·휴강 수(월~일, 오늘 표시), 강사별 정상·휴강 수(합계 많은 순 → 이름순, 강사 없음은 '강사 미정') |
| 화면 | `src/components/dashboard/class-charts.tsx`: 이번 주 회차 조회 → 요일별 세로 막대, 강사별 가로 막대(쌓기). 로딩 스켈레톤·오류·다시 시도·빈 상태·'수업 시간표' 링크. `dashboard.tsx`의 빈 상태 패널 대체 |
| 색 | 정상 `#D63E20`(주 조작색), 휴강 `#2A78D6`. dataviz 검증 스크립트 6개 항목 통과(흰 배경). 앱은 라이트 모드만 사용 |
| 접근성 | 2개 계열이라 범례 표시, 막대 끝에 합계 숫자, 툴팁, 화면에 보이지 않는 표로 정확한 수 제공 |
| 테스트 | 단위: 집계 함수 경계값. E2E: 대시보드 기존 테스트를 새 패널 제목으로 갱신, 이번 주 회차 fixture로 차트 표·강사 행 확인 |
| 문서 | 기능 문서(대시보드), UI 가이드 차트 기준, README·overview 기능 요약, 기획·계획 색인 |

## 작업 순서

1. 의존성 설치, 집계 함수와 단위 테스트
2. 차트 컴포넌트와 대시보드 패널 교체, 스타일
3. E2E 갱신·추가, 1440·768·390px 확인
4. 린트·타입·단위·빌드, 커밋 직전 리뷰, 문서 반영

## 구현·검증 기록

- 2026-10-22: 계획 작성, 개발 시작.
- 구현: `@mantine/charts@^9.7.3`·`recharts@^3.10.1` 추가, 집계 함수(`src/lib/classes/stats.ts`), `class-charts.tsx`, 대시보드 빈 상태 패널 교체·미사용 아이콘/CSS 제거. 색은 dataviz 검증 스크립트 6개 항목 통과.
- 화면 보정: 눈금선을 값 축 방향 실선으로, 390px에서 최댓값 합계가 범례와 겹쳐 값 축에 1칸 여유를 둔 정수 눈금(`valueTicks`)으로 수정. 1440·390px 스크린샷으로 확인.
- E2E 수정: 패널 제목 변경 반영, 본문 스크롤 테스트 높이 650→480px(차트 패널이 650px 안에 들어감), 로그아웃 테스트는 로그아웃 뒤 `/api/classes/sessions` 401만 허용. 원인 확인: 로그아웃의 `router.replace('/login')`+`router.refresh()`가 대시보드를 다시 마운트해 세션 없이 조회한다(반복 실행으로 경로·시점 기록). 다른 401은 계속 실패로 처리한다.
- 검증: 린트·타입 검사·단위 16개·Webpack 빌드 통과. E2E는 대시보드·차트·내비게이션 19개 통과(1440·768·390px 포함). 전체 E2E는 사용자 승인으로 생략(커밋 시점에 실행 중이던 전체 실행 결과는 근거로 쓰지 않음).
- 리뷰: 개발 후 리뷰는 사용자가 중단했고, 커밋 직전 리뷰도 사용자 지시로 생략했다. diff 자기 점검만 수행.
- 커밋: 2026-10-22 사용자 커밋 지시(push 없음).

## 미완료 및 제한

- 정식 코드 리뷰 미실시(사용자 중단·생략). 전체 E2E 미실행(사용자 승인으로 생략).
- 조회 실패 화면과 빈 상태 화면은 자동 검증하지 않았다.
- 로그아웃 직후 대시보드가 한 번 더 조회해 401이 날 수 있다(사용자 영향 없음). 로그아웃 흐름 개선은 후속 과제다.
