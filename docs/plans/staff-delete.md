## 구현 방향 및 영향 범위

기존 직원 관리 화면과 동일한 작은 버튼·Modal을 재사용한다. 변경 대상은 src/components/staff/staff-manager.tsx, src/app/api/staff/[id]/route.ts, 필요 시 서버 삭제 처리 모듈과 tests/staff-delete.spec.ts다. 기존 서버 권한 검증·동일 Origin·JSON 검증을 재사용한다. 구현 전 설치된 Next.js Route Handler 가이드와 최신 Supabase Auth 삭제 문서, 원격 스키마를 확인한다.

현재 staff.id는 auth.users.id를 ON DELETE CASCADE로 참조한다. 새 테이블은 계획하지 않는다. Auth 삭제 전에 서버에서 대상 sub_admin 조건으로 is_active=false와 credentials_reset_at을 갱신해 기존 세션을 차단한 뒤 Auth Admin deleteUser를 실행한다. Auth 삭제 성공 시 FK로 staff도 삭제된다.

부분 실패 정책: 세션 차단 후 Auth 삭제가 실패하면 계정은 비활성 상태로 남는다. 오류에 이를 명시하고 삭제 재시도 또는 관리자 재활성화를 안내한다. 무조건 이전 상태로 복원하거나 성공으로 표시하지 않는다. 삭제 성공 뒤 목록 조회만 실패하면 삭제 성공과 목록 갱신 실패를 구분한다.

## 검증 계획

기존 Playwright를 사용한다. 실제 운영 계정은 삭제하지 않고 이 검증에서 생성한 전용 테스트 계정만 사용한다. 오류 주입은 테스트에서 수행하며 운영용 우회·테스트 API는 추가하지 않는다.

## 구현·검증 기록 (2026-10-22)

- 사용자 기획·작업계획 확정 후 개발했다. 현재 더보기 메뉴·생성 Modal 구조를 재사용했다.
- 설치된 Next.js Route Handler 가이드, Supabase 공식 JavaScript deleteUser 문서와 SDK 타입, 원격 staff 테이블과 FK를 확인했다. 기존 스키마를 그대로 사용했다.
- 서버: DELETE /api/staff/[id], 현재 활성 관리자·변경 완료·동일 Origin·JSON·UUID·본인 아님을 확인하고 sub_admin 조건으로만 비활성화/세션 폐기를 수행한 뒤 hard delete를 호출한다.
- 세션 차단·삭제 실패 단계를 src/lib/auth/delete-staff.ts에서 구분한다. 세션 차단 실패는 삭제 중단, 이후 삭제 실패는 차단 상태와 재시도를 안내한다.
- UI: 삭제 메뉴·대상·영구 삭제 안내·취소·삭제 확인, pending 중 닫기/중복 제출 차단, 성공 후 대상 행 제거와 목록 재조회 실패 별도 표시.
- 취소 후 포커스가 사라지는 문제를 테스트로 발견해 행의 더보기 버튼 ref로 명시적으로 복귀하도록 수정했다. 이름/상태/비밀번호 Modal도 같은 복귀 처리를 사용한다.
- 현재 3002 로그인은 404라 기존 정상 8888 개발 서버를 재사용했다. 127.0.0.1 Origin과 Next 개발 서버의 localhost URL이 달라 초기 설정 요청이 거부됐고 localhost:8888로 맞췄다. 서버의 Origin 보호를 완화하지 않았다.
- 초기 테스트의 비로그인 컨텍스트가 프로젝트 기본 관리자 세션을 상속해 전용 테스트 계정 삭제 요청이 성공한 것을 발견했다. 비로그인/서브관리자 컨텍스트에 빈 storageState를 명시하여 수정했다. 운영 계정은 대상으로 사용하지 않았다.
- 개발 모드 effect 이중 요청 때문에 첫 목록만 성공시키던 오류 주입 테스트가 실패해 실제 삭제 요청 이후부터 목록 조회를 실패시키도록 수정했다.
- 이미 정리된 임시 계정을 teardown이 다시 정리할 때 404를 실패로 취급하던 동작을 멱등 처리로 수정했다. 다른 오류는 그대로 실패 처리한다.
- 삭제 테스트 trace는 비밀번호 기록을 피하도록 끈다. 테스트는 직접 생성한 임시 계정 ID만 finally에서 정리한다.

### 동시 작업 충돌과 검증 격리

다른 화면 작업에서 메뉴를 아이콘으로 바꾸는 변경과 테스트 실행이 겹쳤다. 해당 아이콘·툴팁 구조는 유지하고 필요한 import와 삭제 포커스 ref를 보존했다. 공유 tests/.auth가 다른 실행의 teardown에서 삭제되어 일부 검증이 중단되어, PLAYWRIGHT_AUTH_DIR로 setup·teardown·모든 계정 읽기·storageState 경로를 선택할 수 있도록 했다. 기본 경로는 기존 tests/.auth 그대로이며 이번 검증은 /private/tmp/pcome-delete-auth와 별도 결과 폴더를 사용한다.

- 완료 처리. 커밋 직후 리뷰한 파일 목록과 커밋 tree 및 작업 폴더 상태를 확인한다. 배포·원격 push는 이번 요청에 포함하지 않는다.
