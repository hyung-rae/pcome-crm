## 확정과 구현 방향

2026-10-22 사용자가 기획·작업계획, 관리자 권한, 최초·임시 비밀번호 변경 강제를 확인하여 개발을 시작했다. 로그인은 이메일·비밀번호, 서브관리자는 관리자가 초기 비밀번호를 지정한다. 단일 지점이며 이번 DB 생성 범위는 staff다. members·상품·결제는 제외한다.

인증은 요청별 Supabase SSR 서버 클라이언트와 쿠키를 사용한다. 브라우저는 앱 API를 호출하며 직접 Auth SDK를 초기화하지 않는다. 서버 전용 관리 키는 직원 관리 작업에서만 사용한다. 기존 Dashboard 프레임·Mantine 테마를 재사용한다.

## 구현과 원격 적용 기록

- 설치된 Next.js 16.4.2의 인증·cookies·Proxy·Route Handler 가이드를 읽고 구현했다.
- Supabase 최신 SSR·Auth 관리 문서를 확인했다. changelog.md는 Web 도구의 markdown 응답 처리 오류와 샌드박스 DNS 제한으로 읽지 못해 HTML changelog와 최신 문서로 대체했다.
- @supabase/supabase-js 2.118.0, @supabase/ssr 0.12.7, server-only 0.0.1을 버전 고정·lockfile 기록했다.
- 공개 스키마가 비어 있음을 확인하고 staff 스키마·RLS를 리뷰한 후 Supabase 커넥터 apply_migration으로 원격 DDL을 적용했다. 원격 도구는 DDL에 apply_migration 사용을 지시하므로 로컬 DB 반복 변경 지침과 구분했다.
- CLI migration new로 파일을 생성한 뒤 원격 list_migrations가 반환한 실제 버전으로 이름을 맞췄다. `supabase/migrations/20261022051344_create_staff_auth.sql`과 원격 이력 버전·내용이 일치한다.
- private.staff_session_valid는 호출자 본인의 실제 Auth 세션을 확인한다. private 트리거는 임시 비밀번호 재설정 시 기존 auth.sessions를 삭제한다. 노출 스키마의 공개 SECURITY DEFINER 함수는 없다.
- 직원 생성의 Auth·프로필 부분 실패는 새 계정만 보상 삭제한다. 보상 실패는 성공으로 표시하지 않고 운영 정리를 안내한다.
- 사용자가 추가한 서버 키의 유효성을 확인했다. 키는 출력하거나 문서에 기록하지 않았다.
- 사용자가 지정한 첫 관리자 계정을 생성했다. 초기 로그인 정보는 Git 제외 `.env.admin-initial.local`(0600)에 저장했다. 실제 이름·이메일·비밀번호는 문서에 기록하지 않는다.
- 사용자가 공개 가입 설정을 저장한 뒤 Auth 설정의 disable_signup=true를 확인했다.
- 임시 테스트 계정은 전부 정리했다. 원격 최종 읽기 결과 관리자 1명, 테스트 계정 0명, staff RLS=true다.

초기 실패·수정:

- 샌드박스 DNS 때문에 CLI 다운로드가 실패했다. 승인된 네트워크 실행으로 공식 npm CLI를 사용했다.
- 로컬 8888 서버는 포트 생성 권한 및 기존 Next 개발 서버 잠금으로 실행할 수 없어 이미 실행 중인 localhost:3002를 재사용했다. 기존 사용자 서버는 종료하지 않았다.
- 기존 다른 작업의 .archify 소스 스냅샷이 린트·타입 검사에 포함되어 생성 산출물을 제외했다. 원본 산출물은 수정하지 않았다.
- 직원 목록 effect의 동기 상태 변경 lint 오류를 비동기 요청 콜백과 unmount 취소 처리로 수정했다.
- Mantine 필수 입력 라벨의 별표 때문에 exact 라벨 선택자가 시간 초과했다. input name으로 범위를 지정해 수정했다.
- Next 자체 route announcer도 role=alert여서 테스트 선택자가 겹쳤다. 로그인 form 내부 오류로 범위를 좁힌 뒤 전체 26개 통과했다.

## 개발 후 리뷰

실제 변경 코드·새 파일·SQL·테스트·문서를 검토했다. 공개 가입 차단, 활성 역할 검증, RLS 자기 행 범위, 본인 승격 거부, 서버 키의 server-only 경계, 비밀번호 비저장, 중복 생성과 부분 실패 보상, 재설정 세션 폐기, SQL 이력, 기존 Drawer·LNB 회귀를 확인했다.

- 비밀번호 변경과 관리자 상태 변경의 경쟁을 고려해 updated_at 조건을 사용했다. 불일치는 명시적 오류로 처리한다.
- 연결 실패의 브라우저 메시지가 기술적 fetch 오류를 그대로 표시하지 않도록 공통 한국어 오류로 정리했다.
- 초기 관리자 정보 파일이 이미 있으면 계정을 만들기 전에 중단하도록 수정했다.
- 보상 삭제 실패와 초기 관리자 정보 파일 저장 실패는 운영 복구가 필요한 오류로 구분했다.
- 관련 변경 후 린트·타입·빌드와 전체 회귀 테스트를 재검증했다.
- 미해결 중대 코드 문제는 발견하지 않았다. 아래 제한은 검증 완료와 구분한다.
- 커밋 직전 최종 리뷰는 사용자 최종 확인 후 별도로 수행한다. 다른 작업의 변경을 이 작업 커밋에 임의 포함하지 않는다.
