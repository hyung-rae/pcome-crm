# 그룹수업 시간표 관리 작업계획

- 기능/작업 ID: class-schedule
- 상태: 완료
- 최종 갱신: 2026-10-22
- 확정 기획: [기획](../planning/class-schedule.md)
- 현재 기능 문서: 미구현 — 구현 후 `features/class-schedule.md` 작성

## 현재 요약

A~E 구현, 원격 마이그레이션 2개 적용, 독립 코드 리뷰와 지적 수정까지 마쳤다. 사용자 최종 확인을 기다린다(2026-10-22).
최신 검증: E2E 전체 67개(마지막 전체 실행 66개 통과 + 수정 후 수업 화면 6개 재통과), 단위 14개, PGlite 정책 25개, 린트·타입 검사·Webpack 빌드 통과. 원격 보안 자문 새 지적 없음.
사용자 확인·커밋 직전 리뷰 후 커밋했다. 미검증 항목은 아래 '미완료 및 제한'에 있다.
수업 종류, 강사 표시, 반복 수업, 단발 수업, 회차(실제 수업 일정) 데이터를 새로 만들고 회차는 오늘부터 1년 앞까지 DB에 미리 만들어 둔다. 같은 강사의 시간 겹침은 DB 제약으로 막는다.
A~E 다섯 단계로 나눠 단계마다 사용자가 화면에서 확인할 수 있게 진행한다. 직원 관리(강사 표시, 비활성화·삭제 경고)도 바뀌므로 기존 직원 기능의 회귀 테스트가 필요하다.

## 구현 방향 및 영향 범위

### 핵심 설계 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 반복 수업 저장 | 반복 규칙(`class_series`)과 회차(`class_sessions`)를 따로 저장한다. 회차는 오늘부터 1년 앞까지 미리 만든다 | 회차 단위로 휴강·수정·삭제를 기록할 수 있다. 겹침을 DB 제약으로 보장할 수 있다 |
| 1년 범위 유지 | 모든 시간표 API는 시작할 때 확장 함수를 호출해 무기한·장기 반복 수업의 회차를 오늘+1년까지 채운다. 이미 채워져 있으면 바로 끝난다. 모든 등록·수정은 오늘+1년 이내 날짜만 허용한다 | 스케줄러(pg_cron) 없이 동작한다. 쓰기 전에 항상 범위를 채우므로, 범위 밖에서 나중에 생기는 회차와 겹칠 일이 없다 |
| 겹침 보장 | `btree_gist`를 켜고 회차에 제외 제약을 둔다: 같은 `instructor_id`이면서 시간 범위가 겹치면 안 됨. 단, 정상 상태이고 강사가 지정된 회차에만 적용한다. 시간 범위는 `[시작, 종료)`라서 끝과 시작이 맞닿는 경우는 허용한다 | 동시 요청이 들어와도 DB가 겹침을 최종 차단한다 |
| 겹침 안내 | 쓰기 함수가 저장 전에 겹치는 회차를 모두 조회해 목록으로 돌려준다. 저장 직전에는 트랜잭션 advisory lock으로 시간표 쓰기를 한 번에 하나씩 처리한다 | 기획대로 반복 등록 시 겹치는 날짜를 전부 안내한다. 제약 오류만으로는 한 건만 알 수 있다 |
| 쓰기 처리 | 등록·수정·휴강·삭제·확장을 Postgres 함수(RPC) 하나씩으로 묶어 한 트랜잭션에서 처리한다. 함수는 `service_role`만 실행할 수 있고, 서버 API가 `requireStaff()`로 권한을 확인한 뒤 서버 관리 키로 호출한다 | 기존 직원 API의 패턴(서버 권한 확인 → 관리 키)을 따른다. 여러 회차를 바꾸다 일부만 저장되는 상황을 막는다 |
| 조회 권한 | 새 테이블에 RLS를 켜고, 유효 세션을 가진 활성 직원만 SELECT할 수 있는 정책을 둔다. 일반 사용자에게는 INSERT·UPDATE·DELETE 권한을 주지 않는다 | 메뉴 숨김에 기대지 않고 DB에서도 막는다 |
| '이후 전체' 변경 | 기존 반복 규칙은 선택한 날짜 전날로 끝내고, 선택한 날짜부터 새 규칙을 만든다. 범위 안의 기존 회차는 지운 뒤 다시 만들되, 휴강·삭제였던 날짜는 같은 날짜의 새 회차에 휴강·삭제 상태로 옮긴다 | 지난 회차와 이전 규칙 기록을 보존한다. 확정 정책(휴강·삭제 유지, 수정은 덮어씀)을 충족한다 |
| 반복 회차 삭제 | 반복 회차는 '삭제됨' 상태로 남기고 화면에서는 숨긴다. 단발 수업은 실제로 삭제한다 | '이후 전체' 변경과 1년 범위 확장 때 지운 날짜가 다시 생기지 않게 한다 |
| '이후 전체' 휴강 | 반복 규칙에 휴강 시작일을 기록한다. 그 날짜 이후의 기존 회차는 휴강으로 바꾸고, 확장으로 새로 생기는 회차도 휴강으로 만든다. '이후 전체 휴강 취소'는 선택한 날짜부터 휴강 회차를 모두 정상으로 돌리고 겹침을 다시 검사한다 | 무기한 반복 수업에서도 휴강 상태가 유지된다 |
| 강사 제외 처리 | staff 트리거가 처리한다. 강사 표시가 해제되거나 직원이 비활성화되면 그 직원이 맡은 앞으로의 회차와 진행 중인 반복 규칙의 강사를 비운다. 회차·규칙의 강사 FK는 `ON DELETE SET NULL`로 둔다 | 기존 삭제 흐름이 Auth 삭제 전에 먼저 비활성화하므로, 트리거 하나로 해제·비활성화·삭제 세 경우를 모두 처리한다. 영구 삭제는 FK가 지난 회차의 강사까지 비운다 |
| 시간 기준 | 모든 일정 계산은 `Asia/Seoul` 기준이다. 저장은 `timestamptz`로 한다. 지난 회차는 시작 시각 ≤ 현재 시각인 회차다 | 기획의 한국 시간 기준. 진행 중인 회차도 '지난 회차'로 보호한다 |

### 데이터 (새 마이그레이션)

- `staff.is_instructor boolean not null default false`를 추가한다.
- `class_types`: 이름(1~30자, 사용 중인 종류끼리는 대소문자·앞뒤 공백 무시하고 중복 불가 — 부분 유니크 인덱스), 기본 정원(1~100), 기본 소요시간(10~240분, 5분 단위), 색상(고정 팔레트 8종 키), 사용 여부, 생성·수정 시각.
- `class_series`: 수업 종류, 강사(null 허용), 요일 배열(ISO 1~7), 시작 시각(5분 단위), 소요시간, 정원, 시작일, 종료일(null이면 무기한), 휴강 시작일(null 허용), 생성 완료일(어디까지 회차를 만들었는지), 생성 직원.
- `class_sessions`: 반복 규칙(단발이면 null), 원래 날짜(반복 회차 식별용, `(series_id, 원래 날짜)` 유니크), 수업 종류, 강사(null = 강사 미정), 시작·종료 시각, 정원, 상태(`scheduled`·`cancelled`·`deleted`), 개별 수정 여부, 생성 직원. 제약: 종료 > 시작, 같은 날 안에서 끝나야 함, 강사 겹침 제외 제약.
- 수업 종류는 FK `ON DELETE RESTRICT`로 둔다. 이번 범위에는 수업 종류 삭제가 없고 사용 중지만 있다.
- RPC: `class_extend_series()`, `class_create(...)`, `class_update(...)`, `class_set_status(...)`, `class_delete(...)`. 각 함수는 advisory lock → 확장 → 입력 검증(강사 활성·표시, 종류 사용 중, 미래 범위, 지난 회차 아님) → 겹침 목록 조회 → 저장 순서로 처리하고 `{ ok, conflicts }`를 돌려준다.
- 원격 적용 전에 원격 마이그레이션 이력과 대상 프로젝트를 확인하고, 적용 직전에 사용자에게 다시 확인받는다. 스키마와 RPC는 마이그레이션 1개(`20261022085919_create_class_schedule`)로 적용했고, 리뷰 수정은 보정 마이그레이션(`20261022093926_fix_class_schedule_following`)으로 적용했다. 이미 원격에 적용한 마이그레이션 파일은 고치지 않고 새 마이그레이션으로 수정한다.

### 서버 API (기존 `readBody`·`requireStaff`·`failure` 재사용)

| 경로 | 동작 | 권한 |
|---|---|---|
| `GET/POST /api/classes/types`, `PATCH /api/classes/types/[id]` | 수업 종류 목록·등록·수정·사용 중지/재사용 | 비밀번호 변경을 마친 활성 직원 |
| `GET /api/classes/instructors` | 강사로 지정할 수 있는 직원의 id·이름(활성이고 강사 표시된 직원) | 같음 |
| `GET /api/classes/sessions?from&to` | 기간 안의 회차(최대 42일). '삭제됨'은 제외한다 | 같음 |
| `POST /api/classes/sessions` | 단발 수업 또는 반복 수업 등록 | 같음 |
| `PATCH /api/classes/sessions/[id]` | `scope: one/following`, `action: update/cancel/restore` | 같음 |
| `DELETE /api/classes/sessions/[id]` | `scope: one/following` | 같음 |
| `PATCH /api/staff/[id]` `action: instructor` | 강사 여부 변경. 기존 `.eq("role","sub_admin")` 제한의 예외로 모든 역할·본인 허용 | 관리자 |
| `GET /api/staff` | 각 직원에 `is_instructor`와 앞으로 맡은 회차 수를 추가 | 관리자 |

겹침이 있으면 409와 겹치는 회차 목록(날짜·시간·수업명)을 돌려준다. 지난 회차를 변경하려 하면 409, 범위·입력 오류는 400으로 응답한다. 공급자 오류 원문은 노출하지 않는다.

### 화면

- LNB에 '수업 시간표'(`/classes`) 메뉴를 추가한다. 모든 직원에게 보이고 새 16px 달력 아이콘을 쓴다. 페이지는 `requirePage()`로 보호한다.
- `/classes`는 '시간표'와 '수업 종류' 탭으로 구성한다(Mantine Tabs).
- 시간표: 768px 이상(PC·태블릿)은 월~일 × 시간 그리드다. 기본 06:00~23:00을 보여주고, 이 범위를 벗어나는 회차가 있으면 범위를 넓힌다. 768px 미만은 날짜별 목록이다. 주 이동·오늘 이동 버튼과 수업 종류·강사 필터를 둔다. 휴강은 흐리게 '휴강' 텍스트를, 강사가 없으면 '강사 미정' 텍스트를 함께 표시한다(색에만 의존하지 않음).
- 회차를 누르면 상세 Modal이 열린다. 앞으로의 회차에는 수정·휴강/휴강 취소·삭제를 둔다. 반복 회차는 '이 회차만/이후 전체'를 선택한다. 지난 회차는 조회만 된다.
- 수업 추가·수정 Modal에서 단발/반복을 전환한다. 반복이면 요일 다중 선택, 시작일, 종료일(선택)을 입력한다. 수업 종류를 고르면 정원·소요시간 기본값이 채워진다. 겹치면 Modal 안에 겹치는 날짜 목록을 보여준다.
- 수업 종류 탭은 기존 직원 목록의 패턴(표 + 생성 Modal + 더보기 Menu)을 쓴다. 색상은 고정 팔레트에서 고른다.
- 직원 관리: 강사 배지와 더보기 메뉴의 '강사 지정/해제'를 모든 행에 추가한다(관리자 본인 행 포함). 앞으로 맡은 회차가 있는 직원을 강사 해제하거나 비활성화하려 하면 회차 수를 보여주는 확인 Modal을 띄운다. 지금 바로 바뀌는 상태 Switch는 회차가 있을 때만 확인을 거치게 바꾼다. 삭제 Modal에는 회차 수 경고 문구를 추가한다.
- 성공 토스트 문구: 수업 등록 완료, 수업 수정 완료, 휴강 처리 완료, 휴강 취소 완료, 수업 삭제 완료, 수업 종류 등록 완료 등. 기존 토스트 패턴을 따른다.

## 작업 순서

각 단계가 끝나면 관련 테스트와 화면 확인을 거쳐 사용자에게 보여준다. 정식 리뷰는 전체 구현 후 한 번, 커밋 직전에 한 번 한다(기본 절차).

- [x] 0. 본 계획과 테스트 시나리오를 사용자가 확정
- [x] A. DB 기반 + 수업 종류: 스키마 마이그레이션(테이블·제약·RLS·staff 컬럼·트리거) 작성 → 사용자 확인 후 원격 적용 → 수업 종류 API·탭 화면, LNB 메뉴, 빈 시간표 화면
- [x] B. 강사 표시: 직원 API `instructor` 동작, 직원 목록의 강사 배지·메뉴, 강사 목록 API
- [x] C. 시간표 등록·조회: 확장·등록 RPC, 단발·반복 등록, 겹침 차단·목록 안내, 1년 범위 제한, 주간 그리드·모바일 목록·필터·주 이동

- [x] E. 강사 제외: 직원 목록의 앞으로 맡은 회차 수, 강사 해제·비활성화 확인 Modal, 삭제 Modal 경고, '강사 미정' 표시와 재지정

- 함께 바뀐 공통 부분: `Dashboard`에 `description` prop 추가, LNB '수업 시간표', `AppError`에 선택 `data`(겹침 목록 응답), 클라이언트 `api()` 오류에 응답 본문 첨부, `src/proxy.ts` 경로 목록에 `/classes` 추가, 직원 목록 API의 삭제 중 계정 제외와 회차 수 조회 실패 시 기능 저하 처리.
- 사용자 요청 UI 조정(간소 절차): 본문 위 브레드크럼 바를 모든 업무 화면에서 제거했다(본문 영역 확보). 사용자가 직접 수업 탭을 `pills`로, 필터를 `Select`로 바꿨다(탭은 이후 기본 line으로 되돌림).
- 테스트 데이터: 각 테스트는 전용 강사·관리자 계정과 태그를 붙인 수업 종류를 만들고 정리한다. 전역 setup·teardown은 30분 넘게 남은 `pcome-e2e-class-*` 데이터를 지운다. 작업 후 원격의 수업 테이블은 비어 있고 실제 직원 4명은 그대로다. 작업 전부터 있던 `pcome-e2e-*` Auth 계정 5개(15:42 KST 생성, staff 없음)는 제 작업과 무관해 지우지 않았다.

## 미완료 및 제한

- 390px E2E(`시간표 표시와 지난 회차 조회 전용`)는 테스트가 비어 있다고 가정한 날(11.10 화)에 실제 DB 수업('요가-1' 등)이 있어 실패한다. 코드 회귀가 아니며, 테스트 데이터 격리는 후속 과제다.
- 커밋 직전 리뷰 LOW 후속: 자정을 넘겨 화면을 열어 두면 오늘 열 강조(서버 today)와 현재 시각선(클라이언트)이 어긋남, 현재 시각 갱신이 분 경계와 최대 59초 차이, 색상 Radio.Card 8개가 모두 Tab 정지점, 현재 시각 알약 E2E 확인은 08:00~23:00 밖 실행 시 건너뜀.

- 미검증: 삭제 Modal의 회차 경고 문구와 시간표 조회 실패 화면은 자동 검증하지 않았다. Firefox·Safari·실물 모바일은 미검증이다. 배포 환경(Vercel)에서는 실행하지 않았다.
- 원격 DB는 개발·E2E와 같은 프로젝트다. 운영 데이터를 넣기 전에 프로젝트 분리를 권장한다. 배포 앱은 `main` push 전까지 새 테이블을 쓰지 않는다(추가만 했으며 기존 기능 영향 없음).
- 1년 범위 확장은 시간표 API가 호출될 때 일어난다. '이후 전체' 휴강 취소는 그 전에 하루씩 잡은 휴강도 함께 돌린다. 다시 활성화하거나 강사로 다시 지정해도 비워진 회차에 강사가 자동으로 돌아오지 않는다.
- 직원 목록의 회차 수는 불러온 시점의 값이다. 직원 영구 삭제와 수업 변경이 동시에 일어나면 드물게 한쪽이 교착으로 실패할 수 있다.
- 성능 자문 INFO(쓰이지 않은 새 인덱스, `created_by`·`class_type_id` FK 인덱스 없음)는 현재 규모에서 그대로 둔다.
