## 구현 방향 및 영향 범위

설치된 Next.js의 loading 파일 규약을 읽었다. `src/app/loading.tsx`와 필요한 하위 경로 loading 경계에서 계정 정보가 없는 공통 로딩 화면을 재사용한다. 페이지 이동 로딩이 실제로 표시되는지 느린 라우트 응답으로 검증하며, 필요하면 설치된 Next.js 가이드에 따른 Link pending 표시를 함께 사용한다. 임의 시간 지연은 넣지 않는다.

기존 Mantine·브랜드 테마를 재사용한다. 공통 권한 배지를 만들어 직원 목록과 상단바에 적용한다. 직원 목록 최초 조회는 스켈레톤, 재조회는 기존 행과 아이콘 버튼 로딩을 사용한다. 조회 중 조회/변경의 충돌을 막고 오류와 빈 목록을 분리한다.

상태 컬럼 토글은 기존 PATCH API의 action=status와 명시적인 목표 is_active 값을 전송한다. 확인 모달과 더보기 상태 항목을 제거한다. 성공 응답 후 해당 행 상태를 반영하고 오류 시 원래 상태와 행별 오류를 유지한다. 변경 중 충돌 조작·중복 제출을 막고 조회 실패와 상태 변경 성공을 구분한다. 관리자 행은 상태 표시만 유지한다. API·권한·DB 정책은 변경하지 않는다.

예상 코드: `src/app/**/loading.tsx`, 공통 로딩·권한 배지 컴포넌트 및 CSS, `src/components/staff/staff-manager.tsx`·`staff.module.css`, `src/components/dashboard/dashboard.tsx`·관련 CSS, 기존 Playwright 테스트 및 신규 로딩·토글 테스트.

## 구현 순서

1. 공통 로딩·권한 배지와 라우트 로딩 경계를 적용한다.
2. 최초 조회 스켈레톤·재조회 로딩·아이콘 버튼·조회 오류 상태를 구현한다.
3. 상태 컬럼 토글·행별 처리/오류·성공 반영을 구현하고 중복 메뉴·확인 모달을 제거한다.
4. 관련 자동 테스트를 추가하고 기존 메뉴·인증·삭제 테스트를 갱신한다.
5. 린트·타입·Webpack 빌드 및 관련·회귀 테스트를 실행한다.
6. 실제 Chromium 세 화면 크기·키보드·콘솔·실패 요청·캡처 검토를 수행한다.
7. 코드 리뷰와 필요한 수정·재검증, 기능·구조·UI 가이드·색인·현황 갱신 후 사용자 최종 확인 대기로 보고한다.

### 실패·수정·재검증

- 개발 Strict Mode의 초기 effect 중복 호출을 테스트가 단일 호출로 가정해 실패했다. 초기 요청을 모두 해제하고 이후 사용자 재조회 증가분을 검사하도록 보완했다.
- Next 경로 안내용 alert와 앱 오류 alert가 섞여 엄격 선택자 검사가 실패했다. 직원 관리 영역 내부 alert로 한정했다.
- 기존 셀 텍스트 기반 상태 검사는 접근성 스위치 상태 검사로 변경했다. 실제 마우스 테스트가 장식 track의 입력 클릭 가로채기를 발견했다. `.mantine-Switch-track`에 pointer-events:none을 적용해 입력이 클릭을 받게 하고, 키보드 실패/마우스 재시도·실제 API 전체 회귀를 통과했다. 임시 시간 제한 확대는 제거했다.
- 성공 토스트 표시 시 모달 닫기 전환이 끝나기 전에 캡처되던 테스트를 모달 제거 후 캡처로 보완했다. 토스트 수동 닫기·5초 자동 닫기·hover/키보드 포커스 중 유지·동일 문구 재표시 검증을 세 화면 크기에서 통과했다.
- 시간 초과 실행에서 생성된 것으로 정확히 확인한 테스트 이메일 3개만 대상으로 정리했으며 잔여 2개를 삭제했다. 다른 작업에서 생성한 계정에는 손대지 않았다. 최종 성공 실행의 테스트 계정은 기존 teardown/finally로 정리했다.
